# 中文事实证据与表达检查（v2.7 开发版）

输入为已有草稿，新闻稿另附用户素材。用当前环境可用的 Python 执行脚本，不依赖特定机器的解释器路径。每篇设置单独的工作目录 `<WD>`。

## 1. 抽取与来源核验

```text
python <SKILL>/scripts/fp_extract.py draft.md --workdir <WD> [--material material.md]
```

阅读 `extract.md`、`ledger.json` 和 `diagnosis.json`。离线运行可加 `--offline`，但这不能算完成联网文献核查。

对每条事实实际打开来源，保存 URL、原文摘录和判断到 `evidence` 列表。学术元数据只能证明部分书目信息，研究结论需要查看论文内容。新闻稿直接使用素材作为来源，不假定素材描述的活动已在现实世界独立核实。

重点对照主体、指标、数字与单位、时间及范围、研究对象、否定词和引语全文。新增中文数字时长（如“十个月”）必须核对题目素材和来源；不能因使用汉字而跳过核查。来源摘录不要只截研究结论：需要核验发表年份或刊名时，另附该来源页面中包含年份、刊名或 DOI 的准确原文片段，并与结论摘录分别登记。不要根据网页标题猜测内容。将有不同年份、来源或研究对象的事实拆成独立句子并分别登记，避免错误关联年份。保留某项统计数字时保留或依据来源更正其年份；不能只写“6月”而丢失原文中已知的统计年份。同一来源的结论和出版信息可作为多条证据，分别逐字摘录并记录来源；禁止把不同来源的年份和结论机械拼成完整支持。一句多件事可分配多条证据，但其他事实的证据不能抵消某个字段的缺失。数字出现不等于支持原句；“均来自英国”“词错误率”“头两年”等限定同样需要证据。

`agent_verdict` 填 `支持/矛盾/未找到`，摘录来自实际读到的来源。外部网页填真实来源 URL 和逐字摘录；仅对题目提供的素材使用 material.md。没有检索到就标“待验证”，不得当作证据矛盾或事实已证实。表达候选阅读原文后标 `成立/不成立`；重复事实候选应对照前文，保留独有事实与必要上下文，只删除确认重复的部分。具体改写参考 `references/改写指南.md`。

## 2. 生成修改单并处理

```text
python <SKILL>/scripts/fp_verify.py --workdir <WD>
```

脚本检查完整数值、单位、数量范围、完整引语及部分指标/时间绑定。

- `可信`：抽取要素及已实现的局部规则一致，仍不等于整句语义和来源真实性已证实。
- `待验证`：缺少要素、关系不能绑定或属于定性陈述。补充来源并逐项核查；未解决的保留明确的复核状态，或删除。
- `存疑`：证据判断矛盾或局部数值/范围冲突。按证据修改，无法解决则明确转交复核或删除。

为每条陈述填 `action=保留/改正/弱化/删除`，修改句全文填 `new_text`。只加“约”“据报道”不能解决缺证，也不能把来源中的不等式写成精确值。保留原文正确的重要事实，删除、纠正和弱化分别记录。

修改事实后，重新判断证据是否支持修改句，可在同一条记录的 `final_evidence` 填与 `evidence` 相同结构的证据列表。原句的“矛盾/未找到”判断保留在 `evidence`，不要仅改标签伪装完成核验。守门对已登记的修改句优先使用 `final_evidence`；未提供时沿用原证据，并可能继续要求复核。

对拆句、合句及新增数字，将终稿中实际句子逐条填入对应 `new_text`，并为新增或变更的事实提供 `final_evidence`。一条记录无法明确对应时先补登记，不要凭相似度假设已核实。避免为消除待复核提示大量删改或凭空填充；资料不足时保留待复核状态。

保存 `output.md`。篇幅变化尽量在 ±15% 内；守门超过 15% 警告、超过 30% 阻断。不得为维持篇幅补空话。只改有依据的问题，避免无关重写。

## 3. 检查最终稿

```text
python <SKILL>/scripts/fp_guard.py output.md --workdir <WD>
```

守门重新抽取修改稿中的事实，与原句或 `new_text` 精确关联，再用登记证据进行离线复查。新句未登记、有链接但证据仍不足、改写后引入错误，都不能直接放行。

- 退出码 `0`：实现的规则检查通过。
- 退出码 `1`：结构检查失败或最终事实有冲突。
- 退出码 `2`：结构检查通过，仍有事实需要复核（含未找到来源）；不等于规则通过。

查看 `guard_report.md` 和 `guard.json` 的 `ready_for_delivery`、`final_fact_checks`。守门通过也须检查未解决的表达候选与题目要求；规则通过不等于表达合格。最多两轮自动修订后仍未解决的，随交付说明列明未核实内容；不要将复核状态写成检查成功。

## 边界

规则覆盖有限的数值、指标、时间和地域表达，不是通用语义蕴含模型。定性判断、隐含因果、跨段归属和复杂改写仍需独立核查。普通网页摘录可能不完整或错误，接口覆盖不到的文献需另查。抽取器也会漏事实，因此即使规则通过，仍应人工检查关键结论和未抽取的陈述。


终稿和账本须逐条对应：保留、改正、弱化、删除应如实反映终稿；修改句必须登记为终稿实际句子。若提供目标字数，可在 fp_guard.py 中使用 --target-chars 作近似复核；篇幅变化和任务字数分别判断，不通过补充虚构细节或重复空话达标。

素材写作中，检查没有数字的人物活动和第一人称经历：把计划写成已经发生、给人物新增行为，都需要素材依据；不要把常识性解释误当作事实证据。只看过来源摘录时，只能说“给定摘录未提及”，不得声称整篇原文未提及。
