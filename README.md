# zh-fact-polish

面向中文非虚构文本的事实证据与表达检查 Skill。它帮助使用者从已有草稿中识别待核查的内容，登记来源和修改，再对终稿进行复查。

## 项目背景

在中文写作和 AI 辅助写作中，数据的时间、对象或指标可能与来源不一致；文章修改后也可能出现新的事实错误。本项目围绕“已有草稿的交付前检查”设计流程，将事实、证据和修改记录关联起来，方便人工追踪和复核。

项目适用于议论文、报告、科普文章、课程论文和新闻稿等非虚构文本，不适用于小说、诗歌等虚构内容。

## 主要功能

- **抽取待检查内容**：识别草稿中的事实陈述、数字、引语及部分表达问题。
- **登记和核对证据**：记录来源、原文摘录与核验判断，区分支持、矛盾和未找到证据的情况。
- **生成修改单**：记录事实的保留、改正、弱化或删除，并辅助检查表达问题。
- **复查终稿**：检查终稿与已登记的事实、修改及证据是否对应，提示冲突或待复核内容。
- **测试与复现**：提供单元测试和存档样例，用于检查和复现流程中的确定性部分。

## 工作流程

```text
已有草稿 → 抽取待查内容 → 人工或 Agent 核查来源并登记证据
         → 生成修改单 → 修改草稿 → 终稿复查
```

来源核查和文本修改需要由使用者或具备相应能力的 Agent 参与，脚本不会独立完成全部事实核实。具体工作要求和证据登记方法见 `zh-fact-polish/SKILL.md`。

## 运行环境

- Python 3.10 或以上
- 脚本仅依赖 Python 标准库，无需安装额外的 Python 依赖
- 联网查证需要具备联网能力的 Agent，或由使用者提供可核对的来源和摘录

## 快速开始

在源码目录下准备 UTF-8 编码的 `draft.md` 草稿，然后运行：

```bash
# 1. 抽取事实和表达检查候选
python zh-fact-polish/scripts/fp_extract.py draft.md --workdir work

# 2. 阅读抽取结果，核查来源并登记证据后，生成核验结果
python zh-fact-polish/scripts/fp_verify.py --workdir work

# 3. 根据修改单完成修改，保存为 output.md 后复查终稿
python zh-fact-polish/scripts/fp_guard.py output.md --workdir work
```

第二步之前，需要阅读 `work/extract.md`，并按照 `SKILL.md` 的说明填写 `work/ledger.json` 和 `work/diagnosis.json`。新闻稿等有指定素材的场景，可以在抽取时加上 `--material material.md`；仅进行离线流程检查时可加 `--offline`，但离线运行不代表完成联网核查。

终稿复查脚本的退出码：`0` 表示已实现的规则检查通过；`1` 表示结构检查失败或存在事实冲突；`2` 表示结构检查通过，但仍有事实需要复核。

## 项目结构

```text
zh-fact-polish/
├── SKILL.md               # Skill 指令及完整工作流程
├── references/            # 改写指南
└── scripts/               # 抽取、核验和终稿复查脚本
tests/                     # 单元测试
validation/                # 固定验证样例
tools/                     # 辅助工具
reproduce/                 # 确定性流程复现脚本与样例
```

以上为源码包解压后的结构。首次使用前请阅读源码包中的环境与运行说明。

## 测试与复现

在源码目录下运行单元测试：

```bash
python -m unittest discover -s tests
```

运行存档样例的确定性复现：

```bash
cd reproduce
python reproduce.py
```

复现不需要联网或 API Key。模型生成的文章具有随机性，不属于上述确定性复现范围。

## 使用边界

脚本的规则覆盖有限，不能替代人工核实，也不能保证发现所有事实或表达问题。规则通过不等于文章所有事实都真实；对于证据不足、来源未找到或复杂语义无法判断的内容，应明确标记为待复核。使用外部模型或 API 时，请自行配置所需凭据，并避免将密钥提交到公开仓库。
